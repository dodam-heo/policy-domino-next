# 정책도미노 NEXT — 개발·품질·제출 기준

## 제품 목적

공식 정책·법령·행정규칙·자치법규 등의 개정이 **어느 공공기관의 어떤 업무·사업 검토사항으로 이어지는가**를 원천 증거와 함께 추적한다.

공공기관의 범위는 중앙부처·지방자치단체·교육청·공공기관이며 민간조직은 분석 대상에 넣지 않는다. 직제 변경·복지급여는 범용 변경의 **사례일 뿐** 고정 분기, 정답 목록, 하드코딩 대상이 아니다.

## 모듈별 단일 책임

| 모듈 | 역할 |
|---|---|
| `api.py` | 공식 목록 검색, 공포번호·일자·법령 종류·버전 ID 수집 |
| `coverage.py` | 스트림별 독립 이력 수집 커서, 미완료 기간 재조회, 최근·장기 미처리·재시도 비교 대기열 및 범위 통계 |
| `parser.py` | 조문·별표·본문과 원문 완전성, SHA |
| `analysis.py` | 신구 조문 비교, 변경 범주, 명시 수행주체, 공식 조문 인용 |
| `discovery.py` | 공식 관련 규정 탐색 및 정확한 인용 확인 |
| `alioplus.py`, `programs.py` | 실제 공식 공공사업 본문 및 명시적 조문 인용 검증 |
| **`events.py`** | 공식 변경 사건 식별·병합, 근거별 기관·사업 업무 검토사항 구성 |
| `ai.py` | 변경 조문·증거로 확인된 기관·사업에만 AI 추가검토, 응답 근거 검증 |
| `contracts.py` | 전체 사건·원문·기관·AI 근거 계약 검사 |
| `pipeline.py` | 유일한 파이프라인·자료 저장·공개 출력 |
| `presentation.js` | 변경 종류·실제 변경 항목·공공기관 연결 유무를 분리한 동적 목록 필터, 기관별 상세 투영 |
| `app.js` | 사건 중심 목록→상세, 원문·기관별 카드 접기 |
| `index.html`, `styles.css` | 명확한 사용자 정보 계층과 반응형 레이아웃 |

같은 의미 분석을 코드 여러 계층에 중복 구현하지 않는다. 프런트엔드는 새 기관명·업무 수정 의무를 계산하거나 지어내지 않는다.

## 독립적인 주장·근거 단계

1. **수집:** 공식 문서의 ID·공포일·법령 종류·이력
2. **변경:** 비교 가능한 실제 종전·현행 조문의 원문·해시
3. **사건:** 공식 동일 공포 식별자를 공유하는 복수 규정의 묶음
4. **기관 직접 규율:** 해당 기관의 조직·직제 규정 자체가 변경된 사실
5. **조문 명시 수행주체:** 실제 변경 조문에서 역할을 특정할 수 있는 경우
6. **공식 사업 연결:** 공식 사업 원문에 정확한 법령·조문 인용 또는 검증된 중간 경로가 있는 경우
7. **검토사항:** 근거가 확인된 변경 내용과 기관의 담당 운영기준을 대조할 항목
8. **AI 초안:** 위의 검증된 ID·인용 자료에 근거한 추가 분석
9. **실제 반영·조치:** 별도 공식 이행 증거가 있어야 알 수 있으며 현재 구현하지 않음

4~6번은 각각 **다른 근거 수준**이다. 단순 부처명 노출·기관명 등장·주제 유사도로 사업을 확정하지 않는다. 반대로 실제 변경된 직접 규율 대상 업무를 공개 사업 인용이 없다는 이유만으로 화면에서 지우지 않는다.

## 필수 품질 게이트

- **공식 병합:** 같은 공포번호·일자·법령 종류의 중앙 법령은 동일 사건으로 구성; 다른 번호/종류 또는 지방자치법규는 근거 없이 병합하지 않음
- **완전성:** 변경 조문이 빠지거나 다른 사건에 중복 편입되면 계약 실패
- **기관 근거:** 기관별 검토사항의 기관·조문·원문·사업 연결 근거가 확인되지 않으면 실패
- **조치 상태:** 직접 검토 대상은 제공하되, 조치 완료/미조치 여부는 임의 추정 금지
- **AI 검증:** 기관 ID·업무 검토 ID·사업 ID와 직접 원문 인용이 입력 근거에 없으면 실패
- **범용성:** 금액·자격·절차·기한·조직·서식·허가의 별도 합성 사례로 회귀검증
- **화면:** 기본 단위는 정책 사건, AI 사용 여부보다 기관별 업무 변경이 앞. 정책 상세 내 기관명 필터는 해당 사건의 실제 분석 기관 목록으로 자동 구성하며 PC 왼쪽 검색/전체 복귀, 모바일 기관 선택, 다른 사건으로 이동 시 초기화까지 검증. 모바일 목록→상세→뒤로·깊은 링크 정상
- **수집 진도:** 색인 건수와 분석 완료 건수는 다름. 미분석·재확인·재시도 상한·미완료 수집 구간을 분리 표시하고 개별 출처의 수집 실패가 타 출처의 역사적 이력 수집을 가로막지 않아야 함
- **대기열:** 최신 문서만 반복 처리하지 않고 장기 미처리·최근 미처리·재확인 대상 모두 일정한 처리 기회를 확보하며 시간 예산을 넘기기 전에 상태를 저장
- **필터:** 변경 종류·변경 항목·기관 연결 상태는 독립적인 조건, 급여 같은 특정 정책 사례를 최상위 고정 필터로 넣지 않음
- **배포:** Python/JavaScript 테스트, 현재 원천에서 이벤트 재생성 및 공개 데이터 근거 검사 후 Pages 게시
- **코드:** 단일 명령 진입점 및 하나의 워크플로; 이전 저장소나 legacy 결과 의존 금지

## 구현 완료와 남은 개발 구분

### 반영된 소프트웨어

- 원천 문서 검증 후 사건을 독립적으로 구성하는 `events.build_events`
- 직접 규율기관·명시 수행주체·공식 사업 인용의 서로 다른 출처 기반 업무 검토사항
- 증거 검증된 AI 보조 결과의 조문/기관/사업 연결
- 실제 검증 사건에 대한 목록·상세·기관별 묶음·신구 대조 접기
- 사건 병합·기관 증거 위조를 차단하는 회귀테스트와 계약검증

### 미완성·제출 전 별도 실측 필요

- 고시의 첨부표, 각 부처·지자체·교육청·공공기관 사업 운영기준의 전국 수집
- 변경 조문의 직접 언급·직접 인용을 넘어서는 간접 영향 발견율 검증
- 공공기관의 후속 실행 이력 자동 확인
- 대규모 원문 목록과 상세의 증분 저장·분리 제공
- 실제 서로 다른 분야의 정책 사건을 대상으로 하는 정밀도·재현율·누락률 측정

**화면에 분석 결과를 표시했다는 사실만으로 전국 공공서비스 영향분석을 완성했다고 주장하지 않는다.**
