# 정책도미노 NEXT — 단일 프로젝트 아키텍처

## 1. 해결하려는 문제

정책·법령·고시 등 규정 변경이 발생하면 실제로 바뀐 부분을 찾고, 변경된 조항을 참조하는 관련 규정 및 공공기관의 사업·업무자료를 추적하여 **기관별 검토 질문과 공식 근거**를 제공한다. 일반 국민 및 민간 사업자는 기관별 분석 대상에 포함하지 않는다.

정책도미노는 공식 법령 검색의 재포장이 아니다. 핵심은 **공식 변경 → 관련 규정 → 공공기관·사업의 실제 인용 → AI 검토 초안**을 서로 다른 증거 등급으로 연결하는 데 있다. 특정 고시·직제 개편·기관의 예시를 운영 코드의 분기 조건으로 고정하지 않는다.

## 2. 단일 실행 경로

```text
LAW_OC -> LawAPI.search_window()/history()/detail()
          -> parser.parse_document() -> analysis.compare()
          -> discovery.discover_dependents() / analysis.connect_changes()
          -> ALIOPlusClient.collect() / programs.discover_program_links()
          -> [별도 Gemini AI 단계] ai.analyze_batch() (GEMINI_API_KEY)
          -> contracts.validate_public()
          -> pipeline.render() -> site/data.json -> site/presentation.js + app.js
```

유일한 명령 진입점은 `python -m policy_domino {run,ai,ai-check,render}`, 유일한 운영 GitHub Actions는 `.github/workflows/pipeline.yml`이다. 각 모듈의 입력·출력은 다음과 같다.

| 모듈 | 책임 | 주된 결과 |
|---|---|---|
| `api.py` | 법제처 공식 API 조회·기록 수 감사 | 공식 문서 메타데이터·이력 |
| `parser.py` | 실제 조문·별표·부칙 추출 | 완전성 및 SHA가 있는 원문 |
| `analysis.py` | 신구 비교·정확한 조문 인용 검출 | 실제 변경과 확인된 법령 인용 |
| `discovery.py` | 신규 인용 규정을 공식 검색·원문 재확인 | 미등록 규정 발견 감사 |
| `alioplus.py` | 공식 공공사업 페이지 제한 수집 | 사업명·기관명·본문·원천 상태 |
| `programs.py` | 정확한 변경 조문과 사업 자료 인용 연결 | `program_dependencies[]` |
| `ai.py` | LLM 모델 실행·구조화·원문 인용 검증 | `analysis.ai` 검토 초안 |
| `contracts.py` | 출력 증거 계약 및 허위 조치 판정 차단 | 공개 전 유효성 확인 |
| `pipeline.py` | 단일 수집·분석·출력 조율 | `data/state.json`, `site/data.json` |
| `presentation.js` | 순수 정렬·기관별 근거 구분 | 사용자를 위한 표시 모델 |
| `app.js` | DOM·탐색·필터·비교 표시 | 반응형 화면 |

## 3. 증거 등급

1. **공식 변경 사건:** 제목, 버전 일련번호, 공포/발령일, 공식 URL. 아직 조문 비교가 없는 경우 `queued` 유지.
2. **실제 신구 차이:** 종전·현행 공식 원문 대조 및 SHA가 확보된 `compared` 또는 `partial_compared`만 인정.
3. **관련 규정의 인용:** 다른 공식 규정 본문이 변경 조문을 정확히 인용한 경우만 `verified_exact_article_citation`.
4. **공식 공공사업 연관:** 공공사업 원문에서 변경 조문을 직접 인용하거나, 근거가 검증된 관련 규정을 인용하면 `verified_program_citation`. 단, 이는 수정 필요성이 확정된 상태가 아니다.
5. **AI 변경 분석·검토 초안:** 모델이 2~4의 실제 원문을 입력받아 작성. JSON Schema 및 서버 측 직접 원문 인용·기관 ID 재검증이 모두 통과하고 모델명과 출처 해시가 일치해야 `analysis.ai` 표시 가능. AI가 생성한 질문만으로 기관의 의무가 확정되지 않는다.
6. **기관별 조치 확정·이행 완료:** 별도 공식 기준 변경 전후 또는 기관의 조치 증빙이 있어야 하며, 현재 범용 엔진에서 미구현.

발행기관·등장 기관명·법령 제목 일치·검색 엔진의 검색 결과만으로 사업 영향 또는 조치 의무를 확정하지 않는다. **미발견은 영향 없음이 아니다.**

## 4. AI 입출력과 검증

입력은 동일 변경 사건의 공식 신구 조문(최대 3개)과, 실제 인용이 확인된 사업 링크(최대 6개)이다. 전체 요청 크기를 제한하며 외부 문서는 명령이 아닌 자료로 취급한다. LLM은 독립 AI 단계에서 Gemini `models.generateContent`를 호출하고 `responseMimeType=application/json` 및 `responseSchema`를 사용한다. 전체 API 요청 수를 실행당 최대 2회로 제한한다.

출력은 **변경 조문별 차이 요약·검토 질문**, **인용으로 연결된 공공사업별 적용 검토 질문** 두 종류다. 모델이 제시한 이전·현재 문구가 공식 조문에 실제 존재하는지, 기관명·사업ID·조문번호가 검증된 입력에 존재하는지, 사업 인용 문구가 공식 원문에서 유래했는지 다시 검사한다. 위조·누락·형식 오류·모델 실패는 생성 기록으로 인정하지 않는다.

AI 분석 실행 시 `GEMINI_API_KEY`는 서버 환경변수에서만 읽고 `site/`에 복사하지 않는다. 키 미설정 시 `ai_status=not_configured`, 모델 출력 실패 시 기존 확정된 법적 원문 비교와 별도로 오류를 보관한다. 모델명이 기록되더라도 사용자에게는 **'AI 검토 초안 · 실제 조치 필요성 미확정'**으로 표시한다.

해당 변경 사건의 공식 변경 원문이나 연결 사업 근거가 달라지면, 이전 AI 초안은 출처 SHA 비교로 자동 무효화되어 게시되지 않는다. 해당 API 호출 비용과 외부 모델 사용 여부를 README에서 명확히 안내한다.

## 5. 공식 원천의 적용 범위

- 법제처 `law`, `admrul`, `ordin`: 공식 공포/발령 데이터 수집과 조문 이력 확인. 확인되지 않은 이전 본문은 임의 생성하지 않는다.
- 알리오플러스: 실제 사업 목록/상세 페이지 조회. 첫 목록 페이지 일부 수집을 실측했고 포털 전체 **5,379건**이라는 표시와 실제 검증된 수집 건수를 분리한다. 2페이지 이후 전체 순회는 아직 검증되지 않았으며 `complete=false` 유지.
- 중앙부처·지자체·교육청·지방공기업 등의 모든 사업 운영지침·공고를 현재 완전하게 수집하지 못한다.

연결 엔진이 실제 사업을 발견하지 못했다는 사실이 영향이 없음을 의미하지 않으므로 원천별 누락과 오류를 감사자료로 남긴다.

## 6. 저장, 배포, 테스트

`data/state.json`에는 수집 이력·원문·AI 초안을 보존하고, 공개 `site/data.json`에는 개인정보 없이 공식 변경과 검증된 공개 결과를 포함한다. 현재는 단일 JSON을 정적으로 제공하고 있어 **대용량 증분 저장 및 지연 조회는 미완성**이다. 이 상태를 제출 서류에서 완전한 대규모 운영 인프라라고 표기하면 안 된다.

배포 파이프라인은 Python 단위 테스트·JavaScript DOM 회귀테스트·공개 결과 증거 검증을 통과해야만 `main`의 Pages를 배포한다. PR 검증 과정에서는 배포 및 외부 LLM 호출을 하지 않는다.

재현 명령:
```bash
python -m unittest discover -s tests -p 'test_*.py' -v
node tests/test_site.cjs
python -m policy_domino render
python -m policy_domino.contracts site/data.json
```

모델 요청은 테스트에서 가짜 전송 계층으로 재현성 있게 검증한다. 2026-11-10 GitHub Actions #78의 실측에서는 Gemini API가 공식 변경 원문에 기반한 검증 가능 초안 1건을 생성·저장·배포했으며, 다른 1건은 일시적 과부하(HTTP 503)로 처리하지 못했다. 이 사실이 전국 기관 영향분석의 발견율이나 오판정 검증을 완료했다는 뜻은 아니다.


## 7. Gemini 모델 실행 통제와 운영 판정

GitHub Actions 단일 워크플로에서 수집은 Gemini 호출과 분리되어 실행되며, 공식자료 수집 성공 후 저장된 실제 신구 원문과 검증된 공공사업 연결 근거로만 AI 분석을 수행한다. 변경을 확인하지 못한 문서나 단순 추정 연결은 모델 입력에서 제외한다.

Gemini 호출은 성공 수가 아니라 **실제 요청 수(재시도 포함) 기준 2회**를 초과할 수 없다. 500·503·네트워크 일시 장애는 짧은 지연 후 동일 사건을 최대 1회 재시도하되, 남은 요청 예산이 없으면 재시도하지 않는다. 429·인증 실패·모델 미지원은 즉시 중단하며 원문 인용·근거 검증 실패를 성공으로 인정하지 않는다.

검증 통과 초안은 각 변경 사건 ID와 공식 근거 SHA, 모델명을 기준으로 누적·캐시하며 원문이 변경되면 이전 결과를 게시하지 않는다. 다음 실행은 기존에 유효한 결과를 건너뛰고 검증된 다른 변경 사건으로 이동한다.

`ai_run`에는 API 요청 시도, 성공·캐시, 완전 실패, 재시도 횟수와 정형화된 오류 코드를 보존한다. 마지막 `ai-check` 단계는 다음과 같이 상태를 구분한다.

- **성공:** `generated`, `cached`, `no_eligible_changes`
- **경고:** `partial_generated`(일부 검증 초안 생성), 또는 500/503/네트워크 일시 장애만 발생한 `failed`
- **실패:** 키 미설정·인증/권한 오류·모델 미지원·구조화 출력 및 공식 근거 검증 오류 등

경고는 GitHub Actions의 `::warning` 주석으로 표시되어 운영자가 확인할 수 있으며, 공식자료 저장·사이트 갱신의 성공을 허위 실패로 바꾸지 않는다. API 키 및 외부 오류 응답 원문은 로그·공개 사이트에 출력하지 않는다.
