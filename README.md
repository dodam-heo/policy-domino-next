**공식 규범의 제·개정 → 정책 변경 사건 → 영향받는 공공기관의 업무·사업 → 근거가 있는 변경 검토사항**을 추적하는 공공부문 정책 영향 분석 서비스.

중앙행정기관·지방자치단체·교육청·공공기관 등 **공공조직만** 영향 분석 대상으로 다룬다. 특정 기관명·사업명·법령명이나 정책 예시를 분석 로직의 정답으로 하드코딩하지 않는다. 단순한 법령 검색 서비스나 AI 요약 서비스가 아니다.

## 구현 아키텍처

```text
official legal API (law, admrul, ordin)
   ↓ api.py, parser.py            [원천 목록·공포 식별자·공식 버전]
state.documents, state.versions
   ↓ analysis.py                  [실제 신구 차이, 원문 SHA]
state.findings
   ↓ discovery.py + programs.py   [정확한 법령 인용, 실제 공개 사업 인용]
   ↓ events.py                    [공포번호·일자에 따른 정책 사건 구성]
     ├─ change event             [공식 변경 사건 1건, 구성 법령 N건]
     ├─ source changes           [실제 변경 조문·변경 전후·원문]
     ├─ institutional reviews    [직접 규율기관 / 명시 수행주체 / 검증 사업 인용]
     └─ related rules            [별도 근거 등급의 법령 인용 관계]
   ↓ ai.py (optional Gemini)      [확인된 기관·조문·사업에 대한 근거 제한 AI 보조검토]
   ↓ contracts.py                [사건 병합·기관 연결·인용·AI 요약 모두 재검증]
   ↓ pipeline.render()
site/data.json → presentation.js → app.js → index.html
```

**문서(document)**는 원천 수집·검증 기록이고 **정책 사건(event)**은 사용자에게 보여주는 핵심 분석 단위다. 동일한 공포번호·공포일·법령 종류로 공식 동일 사건임이 확인될 때만 여러 법령을 병합한다. 같은 제목이나 주제라는 이유만으로 병합하지 않는다. 신규·개정·폐지 사실과 신구 비교가 확인되지 않은 색인 항목은 변경 사건으로 게시하지 않는다.

## 사용자 화면

첫 화면은 **정책 변경 목록 → 공포·발령일 최신순 → 전체 / 신규 / 개정 / 폐지 / 영향도 큼 → 검색 → 전체 N건·표시 M건**의 간결한 구성이다. 급여·지원기준·변경 항목·기관 연결 단계 같은 복잡한 드롭다운을 첫 화면에 배치하지 않는다. 정책 제목·법령명·소관기관·사업명·변경 유형은 검색으로 찾을 수 있으며, 정책 상세의 기관별 필터는 별도로 유지한다.

**'영향도 큼'의 현재 운영 기준:** 검증된 기관별 검토사항으로 서로 다른 **공공기관 2곳 이상이 확인된 사건**을 보여준다. 이는 공식 근거로 연결된 기관의 *범위*를 나타내는 최소 기준이지 사회·경제적 파급 효과를 확정해 평가한 등급이 아니다. 기관 인용·영향 발견 범위가 불완전하므로 '영향도 큼' 목록에 없다는 이유로 실제 영향이 작다고 판단할 수 없다.

사건 상세:

1. **이번 변경의 핵심**: 묶인 공식 법령과 실제 변경 조문의 핵심 차이
2. **기관별 변경 검토사항**: PC에서는 왼쪽 기관명 필터·검색으로 해당 기관의 업무·사업·조문별 검토사항만 표시하고 '전체 기관'으로 복귀한다. 화면이 좁거나 모바일이면 기관 선택 메뉴를 사용하며, 다른 정책에 들어가면 기관 선택이 초기화된다
3. **공식 신구 대조·근거**: 자세한 전후 원문, 개정 법령 목록 및 관계 규정은 접어서 제공
4. **AI 보조검토**: 원문 검증을 통과한 추가 분석만 해당 업무 카드 및 접힌 상세에 제공

직접 규율기관, 공식 변경 조문에 명시된 수행주체, 공식 사업 문서의 정확한 조문 인용은 **서로 다른 증거 등급**으로 구분한다. 법령 발령기관·주제 유사성만으로 영향기관을 임의 생성하지 않는다. **기관별 검토 대상**과 **실제 후속 조치 완료/미완료**는 전혀 다른 상태이며 현재 후자는 확인되지 않는다.

## 배포와 데이터 갱신의 책임 분리

GitHub Actions 워크플로는 하나(`.github/workflows/pipeline.yml`)이며, **검증 → 공식자료 수집·AI 분석(정기·수동 실행) → 검증된 사이트 단일 배포** 순서로 동작한다.

- **코드 변경(push):** 현재 저장된 공식 근거로 테스트 후 웹사이트 UI를 바로 배포한다. 수집 API·Gemini 호출 때문에 UI 배포가 지연되지 않는다.
- **정기 실행(2시간마다) 및 수동 실행:** 공식자료 수집·신구 비교·Gemini 분석을 먼저 수행한다. 근거 검증을 통과한 결과를 저장하고, 최신 데이터를 사용해 **한 번만** Pages를 배포한다.
- **독립성:** GitHub Pages가 파일 동기화 상태에 머물러도 원천 수집과 AI 분석의 수행 여부를 막지 않는다. `publish`에 데이터를 매달지 않는다.
- **시간 제한:** 사이트 게시 작업은 25분, Pages 배포 작업 자체는 최대 20분까지 허용한다. GitHub Pages 서버 동기화 장애를 직접 해결하거나 성공을 보장하는 설정은 아니며, 20분을 넘으면 원인을 확인할 수 있게 명시적인 실패로 처리한다.
- **CI 알림:** Node.js 20 경고를 줄이기 위해 지원되는 Node.js 24 기반 Actions 버전으로 갱신했다. 종속된 일부 공식 아티팩트 액션의 경고는 별개로 남을 수 있으며 배포 실패의 직접 원인은 아니다.

## 운영·테스트

Python 3.12+, Node.js. 외부 Python 패키지 설치 없이 실행 가능. 단일 GitHub Actions 워크플로 `.github/workflows/pipeline.yml`.

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
python -m policy_domino render
node tests/test_site.cjs
python -m policy_domino.contracts site/data.json

# 공식 수집과 비교 (AI 호출 없이)
python -m policy_domino run --limit 20

# 현재 검증된 조문·기관 근거로 Gemini 보조 검토
GEMINI_API_KEY="발급된 키" python -m policy_domino ai --limit 24

```

GitHub Actions의 `GEMINI_API_KEY` Secret으로만 API에 접근하며 프런트엔드에 키를 제공하지 않는다. 기본 모델은 `gemini-3.1-flash-lite`, 기본 요청 예산은 **재시도 포함 실행당 24회**다. 429는 중단, 503 등 과부하는 제한된 재시도만 수행하고 처리된 초안은 해시 기준으로 재사용한다. 실제 무료 한도는 AI Studio 프로젝트/모델의 제한을 따른다.

## 변경 내용의 사용자용 설명

**신구 조문 비교의 근거 수준을 구분합니다.** 인용 조문 번호만 바뀐 경우에는 정책 내용 변경이라고 과장하지 않고 인용 수정으로 표시합니다. 서로 다른 기관·사업명 표현이 등장한 경우에는 동일한 제도나 조직이 명칭만 바뀐 것으로 단정하지 않습니다. 종전/현행 본문이 `③` 같은 항 번호만 수집됐다면 원문 불완전으로 처리해 변경 내용을 확정하지 않습니다. 새로운 원문 수집에서는 비교 대상에서 제외하고 재확인 목록에 남깁니다.

주요 변경 미리보기는 무작정 처음 세 조문을 보여주지 않고, **내용 변경의 직접 근거와 해당 공공기관·사업의 검토사항 연결 여부**를 고려해 선정합니다. 확인된 AI 요약은 원문 비교와 혼동하지 않도록 'AI 보조 요약'으로 표시하며, 근거가 없는 자연어 영향 설명을 생성하지 않습니다.


법령 API의 신구 원문은 `analysis.py`에서 원본과 해시를 보존하고, 사용자에게 보여줄 설명은 `meaning.py`에서 **단어 단위로 다시 비교해 생성**합니다. 과거의 16글자 문자 조각을 잘라 이어 붙이는 방식은 사용자 화면에 사용하지 않습니다.

- **변경 유형과 실제 문구를 구분:** 금액·수치, 공고·공표, 자격·선정, 처리절차 등 해당 조문의 변경 부분에 있는 단어로 설명을 구성합니다.
- **변경 전/후 별도 표기:** 변화가 일어난 표현을 각각 온전한 단어 단위로 보여주고, 긴 조문 전문은 펼쳐서 확인합니다.
- **주요 내용 우선:** 단순 표기·문장부호 변경보다 실제 수치·기준 변경과 다른 유형의 중요한 조문을 먼저 표시합니다. 상위 3건은 검토 편의를 위한 미리보기이며 법적 중요도 확정이나 전체 변경의 대체물이 아닙니다.
- **정확한 사건 묶음:** 같은 공포번호·공포일만이 아니라 구체적인 법령 종류까지 확인돼야 병합합니다. 법령 종류가 불명확한 자료는 별도 사건으로 남겨 잘못된 묶음을 방지합니다.
- **근거 검증:** `contracts.py`가 변경 전·후 원문을 바탕으로 설명·미리보기 순위를 다시 계산해 출처와 어긋나는 표현의 배포를 차단합니다.

## 공공기관 영향 연결과 AI 분석 진도

공식 공포 변경을 분석한 후, 변경된 조문을 정확히 인용한 **다른 공식 행정규칙·자치법규·법령**을 추적해 해당 규정의 소관 공공기관을 검토 대상으로 연결합니다. 실제 법령 본문과 인용 조문, 공식 문서 URL을 확인한 경우에만 연결하며, 단순한 기관명 유사도는 사용하지 않습니다. 실제 사업 집행·조치 완료까지 증명한 것으로 표시하지 않습니다.

관련 규정 탐색은 `discovery.py`에서 검색 페이지·검색 결과 오프셋을 저장해 여러 실행에 걸쳐 이어서 확인합니다. 첫 페이지만 보고 전국 조사 완료로 표시하지 않습니다. 공식 공공사업 링크는 알리오플러스의 확보한 실제 사업 본문과 법령 인용에 한정되며, 이 포털이 중앙부처·지자체까지 포괄하는 전국 사업 데이터는 아닙니다. 알리오플러스는 별도 Open API도 제공하지만 별도의 인증키 신청·연계가 필요한 데이터 경로는 아직 연결되지 않았습니다.

Gemini는 문서별로 첫 3개 조문만 보고 종료하는 대신 **모든 실제 변경 조문을 3개씩 독립된 입력 묶음으로 나누어 순차 누적**합니다. 실수로 틀린 인용 하나가 포함돼도 정확한 다른 인용은 개별 검증을 통과한 경우에만 저장하며, 잘못된 항목은 버리고 건수를 기록합니다. 출처 없는 기관·사업은 추가하지 않습니다.

사이트에는 전체 변경 조문 중 **AI가 검증한 조문 수**, 최근 API 호출/신규 결과/오류, 실제 공식 사업 인용·공식 규정 소관기관 연결 건수를 별도로 보여줍니다. 이는 '확인된 검토 대상'과 '실제 조치 완료'를 구분하는 상태입니다.

## 수집·분석 범위와 미처리 문서 처리 방식

데이터의 총색인 건수와 서비스에 나타나는 정책 변경 사건 수는 다르다. 색인된 모든 문서는 공식 신구 원문을 비교한 것이 아니므로, **아직 미분석·재확인 대상·재확인 유예** 문서 수를 홈페이지에 별도로 공개한다.

수집은 최근 7일 구간과 과거 7일 구간을 분리한다. 과거 이력의 날짜 커서는 법률·행정규칙(제정/개정)·자치법규(제정/개정)의 **각 스트림에 독립된 절대 날짜로 보존**되어, 한 출처의 오류 때문에 다른 출처의 수집이 멈추지 않는다. 실패한 과거 구간은 이후 실행에서 같은 날짜를 재시도하며, 공식 원문 확인이 완료되기 전까지 이력을 다 확보했다고 표시하지 않는다.

미처리 문서의 처리 대기열은 **최근 미처리·오래 대기한 미처리·오류 재확인**을 교대로 선정한다. 오류 재확인이 4회 이상 연속 실패해도 영구 제외하지 않고 2일에서 최대 30일 간격의 단계적 유예 후 다시 시도한다. 신구 비교는 정해진 시간 예산이 되면 중단하고 완료된 부분만 저장하므로 GitHub Actions의 시간초과로 대량 처리를 전부 잃지 않도록 한다. 자동 실행은 2시간 간격이며 공식 색인 재조회는 6시간 주기로 제한해 나머지 실행 시간을 누적 신구 비교에 활용한다. 검증되지 않은 문서를 가짜 변경 사건으로 표시하지 않는다.

**제약:** 현재 공식 검색 대상은 국가법령정보센터의 법령·행정규칙·자치법규 3개 계열이다. 고시 첨부표, 부처별 사업 공고·지침, 교육청·지자체·공공기관 서비스, 운영시스템 실제 적용기준을 전국 단위로 완전 수집하는 별도 커넥터는 아직 개발이 필요하다. 속도·백필 개선만으로 그런 자료까지 확보됐다고 주장하지 않는다.

## 공공기관·사업 정보 확장 — 정부24 전국 공공서비스

법령·행정규칙·자치법규 외에 **행정안전부 공식 정부24 공공서비스(혜택) OpenAPI** `https://www.data.go.kr/data/15113968/openapi.do`를 독립 데이터 원천으로 연결했다. `policy_domino/gov24.py`는 공식 `serviceList`, `serviceDetail`의 목록·상세를 수집하면서 서비스 ID, 실제 소관기관명·유형·기관코드, 서비스명, 지원대상, 선정기준, 지원내용, 신청방법, 법령·행정규칙·자치법규 근거를 그대로 보존한다. 수집 페이지 위치는 각 엔드포인트별로 저장하며 실패 시 수집 완료를 선언하지 않는다.

**필요한 설정:** 공공데이터포털에서 위 API의 활용신청(자동승인)을 한 후 GitHub 저장소 Secrets에 `GOV24_SERVICE_KEY`를 등록한다. 등록 전에는 `not_configured` 상태와 기존 공식 데이터만 공개하며, 실제 서비스가 확보된 것처럼 표시하거나 예시 데이터를 넣지 않는다. GitHub Actions 정기·수동 실행에서 `python -m policy_domino gov24 --page-budget 3`으로 누적 수집한다.

`gov24.py`는 실제 서비스의 근거법령에 **변경 법령명이 정확히 명시**된 경우에만 탐색 후보를 생성한다. 근거에서 **변경 조문까지 인용한 경우**와 법령명만 등장한 경우는 서로 다른 수준으로 표시한다. 변경 전 금액과 공식 서비스 선정·지원기준에 동일한 값이 있을 때는 그 원문 사실만 덧붙인다. 이들은 어디까지나 `candidate_not_confirmed`이며 실제 사업 수정 의무나 조치 완료로 변환되지 않는다.

정책 상세의 ‘연결 가능한 공공서비스 · 추가 확인 대상’은 확인된 **기관명·실제 서비스명·인용 근거·확인할 업무·공식 링크**를 별도 카드로 제공한다. 기존의 근거 검증된 기관별 검토사항과 구분해 수집 공백으로 인한 과장이나 기관 목록 하드코딩을 막는다. 후보 근거는 공개 계약 `gov24_contract.py`가 공식 서비스 원천과 다시 대조한다.

이 데이터는 **수혜성 공공서비스 중심**이며 모든 인허가·조달·행정업무 시스템을 포괄하지 않는다. 이후 다른 공식 기관·사업·서비스 데이터 원천을 동일한 근거 계약에 맞춰 연계할 수 있으나, 연결되지 않은 수집기를 구현했다고 주장하지 않는다.

## 고시·공고·지침 수집과 기관별 적용기준

법제처의 공식 행정규칙 API는 `knd=1~6`으로 훈령·예규·고시·공고·지침·기타를 구별한다. 이제 각 분류의 현행·연혁 기록을 독립적으로 수집·재시도하고 공식 종류를 문서에 보존한다. 기존 행정규칙 수집 날짜를 승계하며, 색인됐지만 신구 비교가 안 된 자료는 분석 대기로 표시한다. 고시 별표가 첨부파일로만 제공되면 본문 기준금액을 임의 생성하지 않고 첨부 원문 미분석 상태를 유지한다.

정부24 공공서비스는 실제 기관·사업의 `선정기준·지원대상·지원내용·신청방법·신청기한` 중 검토할 항목을 변경 조문과 연결한다. 서비스 원천에 종전 수치가 존재하는 경우에만 개정 후 기준과 직접 대조하도록 안내하고, 실제 적용 여부는 검토 후보로 남긴다. 공개 데이터 검증은 서비스ID·소관기관·법령 인용·사업 항목·기준 금액을 공식 원문과 다시 대조한다.

정책 상세 첫 화면은 핵심 변경 설명만 표시하고 변경 전후 발췌와 공식 조문 전문은 펼쳐보도록 한다. 공공서비스별 검토 기준은 기관·사업명 아래에 표시하며 근거 문구와 등록 원문은 별도로 펼칠 수 있다.

### 대량 수집 보호와 연도별 고시 비교

공식 행정규칙 6종을 현행·연혁별로 조회하되, 수집 시간 예산을 넘기면 확인한 기록은 보존하고 미조회 종류의 커서를 유지한다. 다음 실행은 마지막 미조회 종류부터 계속 처리한다. 고시가 포함된 행정규칙 분석 대기열은 공식 종류별로 균등하게 교대하며, 제목에 연도가 들어가는 연례 규정은 국가법령정보센터가 문서화한 현행(nw=1)과 연혁(nw=2) API를 각각 사용해 전년도 같은 제목의 근거를 찾는다. 이 기능은 중위소득 등 특정 고시를 하드코딩하지 않는다.

## 현재 제한

- 법제처의 공식 원천과 조문 원문을 계속 수집하지만, **수집 색인 전체가 신구 대조·기관 영향 분석 완료된 것은 아니다**.
- 알리오플러스 기관별 사업은 현재 **첫 페이지 일부 상세자료만** 수집하며 전국 기관의 실제 사업·내부 운영 규정을 포괄하지 않는다. 정확한 조문 인용이 없더라도 실제 영향을 받는 업무가 있을 수 있다.
- 관련 법령 인용만으로 실제 사업 수정 의무를 확정하지 않으며, 공공기관의 조치 완료 여부를 관측하는 엔진은 미구현이다.
- 공개 데이터는 아직 단일 JSON이므로 지연 조회·증분 DB 저장은 개발 과제다.
- 테스트에 나오는 정책·기관은 합성 예제이며, 구 프로젝트의 표시 결과는 현재 분석 데이터로 복사하거나 가져오지 않는다.
